# QA Agent Kit

Portable AI + deterministic-runner QA system for Next.js + Supabase + Vercel projects.
Drops into any repo as `.claude/qa/` via `install.sh`. Mirrors the
[Production Change Playbook](../Production-Change-Playbook/) distribution pattern.

## Model

```
┌─ orchestrator ─┬─ discovery (read-only, writes manifest.json)
                 │
                 ├─ specialists × N  (parallel; read manifest, write raw/<name>.json)
                 │     ├ auth-rls           (two-tenant + anon isolation)
                 │     ├ data-lifecycle     (write→read→cache trace)
                 │     ├ ui-flows           (Playwright journeys)
                 │     ├ integrations       (sandbox only — never real)
                 │     ├ performance        (N+1, query plans, bundle, Lighthouse)
                 │     ├ accessibility      (axe-core + heuristics)
                 │     └ security           (service-role exposure, secret leaks, XSS)
                 │
                 ├─ judge (dedupes, prioritizes, kills flakes → findings.json)
                 │
                 └─ reporter (→ summary.md)
```

**Hybrid model:** deterministic runners (Playwright, Vitest, SQL harness, axe-core)
do the regression-grade testing. AI specialists interpret runner output, hunt for
bugs tests can't express, judge UX, and verify user intent.

## Install into a repo

```bash
cd /path/to/repo
~/Desktop/QA-Agent-Kit/install.sh
```

This creates:
```
<repo>/.claude/agents/qa-*.md       ← subagent definitions
<repo>/.claude/commands/qa-*.md     ← slash commands
<repo>/.claude/qa/
  ├── config.json                   ← edit this once per project
  ├── manifest.json                 ← generated by qa-discovery
  ├── tests/                        ← generated test files (Playwright, RLS, etc.)
  └── reports/<timestamp>/          ← run outputs
      ├── summary.md
      ├── findings.json
      └── artifacts/                ← screenshots, traces, query plans
```

## Use

In Claude Code, in the target repo:

```
/qa-bootstrap     ← first run: detect framework, scaffold config.json
/qa-full          ← entire suite
/qa-feature <name>← single feature (planned)
/qa-since main    ← only what changed on this branch (planned)
/qa-watch <url>   ← post-deploy smoke (planned)
```

## Safety (Production Change Playbook compliance)

- **Tier 0 default.** Discovery is pure read-only. Specialists default to test/sandbox.
- **Refuses production.** Suite aborts if `config.supabase.mode === "production"` or
  if any URL appears in `_safety.production_urls_blocklist`.
- **Integration sandbox-only.** Stripe → test mode. Resend → sandbox + recipient
  override. Webhooks → signature verify, never side-effect prod.
- **Kill switch.** Create `.claude/qa/PAUSE` to stop a run mid-flight.
- **Audit log.** Every API call + every DB write logged to `reports/<ts>/audit.log`.
- **Two-tenant isolation proof** is mandatory for any RLS change verification —
  not "the policy applies" but "tenant B literally cannot read tenant A."

## Specialist coverage

| Specialist | Method | Runner | Catches |
|---|---|---|---|
| qa-auth-rls | dynamic | `runners/rls/run-rls-tests.mjs` | cross-tenant + anon SELECT/UPDATE/DELETE leaks, `user_metadata` in policies, missing per-command policies |
| qa-data-lifecycle | dynamic | `runners/playwright/data-lifecycle.mjs` | phantom success (form claims save, no DB row), stale display after submit, cache invalidation gaps |
| qa-ui-flows | dynamic | `runners/playwright/ui-flows.mjs` | console errors, 5xx, page errors, broken auth redirect, mobile horizontal scroll |
| qa-accessibility | dynamic | `runners/playwright/accessibility.mjs` | WCAG 2.1 AA violations via axe-core (aggregated across routes) |
| qa-integrations | mixed | direct Bash (grep + targeted sandbox calls) | webhook signature gaps, missing idempotency, secrets in client, recipient-override misses |
| qa-performance | mostly static | direct Bash (grep + optional Lighthouse) | N+1 query patterns, heavy deps, `<img>` over `next/image`, large committed images |
| qa-security | mixed | direct Bash (grep + targeted probes) | hardcoded secrets, service-role in client, unauth'd API routes, XSS reflection, open redirects |

First validation target: **CRM-Eco** (3 apps, multi-tenant, RLS, real PHI/PII risk).
